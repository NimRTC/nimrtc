## 1. Motivation

v0.9.2 was tagged today (2026-09-14) as the first feature-complete RC. The
release tag is on `main` and the working tree is clean. Three open items
block the natural "now start P2" flow:

1. **CHANGELOG hygiene.** `## [Unreleased]` in `CHANGELOG.md` still
   contains the vendor tooling, release workflow, HW backends, Opus RFC 7587
   implementation, DTLS Chrome fixes, engine PIMPL refactor, and ~26 new
   module tests — all of which are **already in v0.9.2** but were never
   moved under `## [0.9.2]`. Reviewers and external readers see a v0.9.2
   release with a "release-candidate-only" summary and a giant "Unreleased"
   pile that contradicts the tag.
2. **PAL seam.** `docs/plan/pal-architecture.md` §4 Slice 1 (~50 LOC,
   zero-runtime-overhead inline forwarders) has design agreed but no code
   landed. Slice 1 is a pure mechanical refactor — it cannot regress the
   7 currently-passing `tests/test_engine_plugin_loading.cpp` subtests.
3. **Three v0.9 open decisions** (`#6` 遥操作指标口径 / `#7` Profile JSON
   形态 / `#10` 中文文档形态) need to be closed before they leak into
   reviewer comments for every PR that touches the affected surface.

v0.10.0 closes all three. **No P2 features.** P2 content (DataChannel
互通, in-process SFU, PCM tap 落地, Profile 库官方化) lands in v0.11.0.

## 5. Risk & mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| PAL Slice 1 silently breaks audio3a / codec / video_codec plugin resolution on Windows | Low | High (Chrome interop regression) | Gate on `tests/test_engine_plugin_loading` + Case D e2e before tag. `pal::*` is a literal inline forward to `reg.get_*()` so the regression surface is the inline call site itself. |
| CHANGELOG split loses or duplicates entries | Medium | Low (recoverable) | Use `git log v0.9.0-rc1..v0.9.2 --oneline` to enumerate what shipped; cross-check against the `[Unreleased]` body before deletion. |
| v0.9 Profile-JSON open question turns into a de-facto schema commitment that future PRs must obey | Medium | Medium | ADR-010 explicitly states "JSON schema versioning follows SemVer: any profile-format breaking change bumps MINOR"; v0.10.0 pins schema v1.0 with the existing `profiles/*.json` files as canonical v1.0. |
| 中文文档布局 creates contributor confusion with existing `docs/zh/` file | Low | Low | ADR-012 says `docs/zh/` becomes the canonical Chinese home; the existing single-file content is rewritten into `docs/zh/architecture.md` (the new canonical, replacing the old filename). |
| HYGIENE-1 removes a `build_*` dir that an active script still references | Low | Medium | Run `git grep -l "build_audit\|build_dtls_test\|..."` before deletion. If anything references, keep that one. |
| Release workflow (REL-1) discovers VERSION mismatch on tag | Low | High (tag must be re-cut) | The v0.9.2 fix in `ad960eb` shows this trap; add a pre-tag check in `release.yml` that asserts `VERSION` file content == tag. |

## 6. Release notes draft (skeleton)

To be expanded into `docs/plan/v0.10.0-release-notes.md` before tag.

```
## v0.10.0 — Tech Preview consolidation

This release closes the v0.9 tail and lands one structural refactor.
**No new protocol or content features.** P2 content (DataChannel interop,
SFU relay, PCM tap 落地, Profile 库) is queued for v0.11.0.

### Highlights

- **PAL Slice 1** (Plugin Adaptation Layer): engine now resolves audio3a /
  codec / video_codec plugins through a single `pal::*` seam. Zero runtime
  overhead; public API unchanged. Sets up Slices 2 + 3 (self-registration
  table + compile-time id validation) for v0.10.x patches.
- **CHANGELOG hygiene**: the historical detail of v0.9.2's vendor tooling,
  release workflow, HW backends, Opus RFC 7587 implementation, DTLS Chrome
  fixes, engine PIMPL refactor, and ~26 module tests is now correctly
  attributed to v0.9.2 (previously sitting under `[Unreleased]`).
- **v0.9 open decisions (closed by ADRs)**:
  - #6 遥操作指标口径: engine 只背"单跳预算"，端到端由集成方负责
    (DB31/T 1505—2024 / T/SSITS 2003—2023 as reference). See ADR-011.
  - #7 Profile JSON 形态: JSON is first-class declarative format; existing
    `profiles/*.json` pinned as schema v1.0. C++ Builder remains first-class
    alongside. See ADR-010.
  - #10 中文文档形态: `docs/zh/` subdirectory is canonical Chinese home;
    independent site deferred. Existing `NimRTC-V2-技术文档.md` is
    replaced by `docs/zh/architecture.md` as the new canonical. See
    ADR-012.

### Notes

- 国密后端 (SM2/SM4) remains P4 / Enterprise — not in v0.10.0.
- API still **experimental / not for production** through v1.0.0.
- No binary artefacts shipped (源码为主).
```

## 7. Rollback / abort criteria

If at any point before tag cut we discover:

- PAL Slice 1 regresses any plugin-resolution test on Windows **or** Linux
  → revert `PAL-1` + `PAL-2`, cut **v0.10.0-rc1** instead with PAL deferred
  to v0.10.x patch.
- v0.9 open decisions (遥控 / Profile JSON / 中文 docs) get push-back during review that
  materially changes scope → revert the corresponding ADR and re-scope v0.10.0 to
  chlog + PAL only.

## 8. Timeline expectation

Per §13 baseline (~3 months per minor with 2 weeks of buffer for
interruption), this milestone is **small** (≤ 12 commits, no new
dependencies, no new modules). Realistic schedule:

- Week 1: HYGIENE-1 + CHLOG-{1,2,3,4} + ADRs {010, 011, 012}
- Week 2: PAL-{1, 2, 3} + ADR-009 + DOC-1 + REL-1
- Week 3: tag cut, draft release review, publish

Total: ~3 weeks wall-clock. **No commercial engagement during this
window** — P0–P2 阶段不接商业项目是 §16 的开源基线纪律之一。
