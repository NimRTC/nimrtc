# NimRTC v0.10.3 — Release Notes

> Status: **Tech Preview** — no API stability commitment through v1.0.0.
> Tag: `v0.10.3` · Target date: 2026-09-18 · Owner: BDFL

## Summary

v0.10.3 is a **CHANGELOG-hygiene + Slice 7.5 lock** patch on the v0.10 line:

1. **CHANGELOG retroactive attribution** for PAL Slice 2 + Slice 3. That
   work landed in commit `446e8a0` and shipped in **v0.10.1**, but the
   `[Unreleased]` block in `CHANGELOG.md` was never promoted at release
   time (the same hygiene drift that v0.10.0 fixed for v0.9.2). This tag
   moves the descriptive entries into the `[0.10.1]` section under a
   "**Added retroactively in v0.10.3**" sub-heading so the historical
   record matches the code tree at the v0.10.1 tag. **No new code, no new
   tests, no public API change are introduced by the hygiene pass.**
2. **PAL Slice 7.5** — the first real `WebRtcClassicStack` factory that
   composes ICE + DTLS + RTP + SCTP through the typed `register_transport_stack()`
   registry hook introduced in v0.10.2. Before Slice 7.5, `get_transport_stack()`
   returned the Slice-8 shell `CapabilitySelectorStackFactory` (id `"default"`);
   after this tag, `get_transport_stack("webrtc-classic")` returns a real factory.
   CapabilitySelector rule 1 (needs_browser_interop == true) now resolves to the
   actual ICE+DTLS+RTP+SCTP composition.
3. **Root-cleanliness sweep** — deleted local-only stray files
   (`sslkeylog.log`, `Testing/`, `src/engine/src/engine.cpp.lock`) and
   added defensive `.gitignore` patterns (`*.lock`,
   `src/engine/src/*.lock`) so the same class of residue cannot return.
   **No tracked files changed.**

Net commit count since v0.10.2: **1 source commit** (`7d3a92d`, Slice 7.5) +
**1 hygiene commit** (this release's CHANGELOG + release notes + version
bump + README sync). Net source diff vs v0.10.2: 6 files / +483 −28 lines
(Slice 7.5 only — all of it confined to `src/transport/`, `tests/`, and
`docs/plan/transport-selection.md`).

## Highlights

1. **`WebRtcClassicStackFactory`** registered with id `"webrtc-classic"`
   through the existing `core::PluginRegistry::register_transport_stack()`
   hook from v0.10.2 (Slice 8). Composes the four real backend singletons:
   `IICETransport` (libjuice), `IDtlsSession` (wolfSSL),
   `IRtpSession` (nim-rtp), `ISctpSocket` (Slice 5 stub) — all resolved
   through the plugin seam, none via concrete-`new`. Lifecycle methods
   (`start()`, `close()`, `tick()`) are wired through.
2. **Shell capability selector preserved at id `"default"`** for backward
   compatibility with any v0.10.2 caller that already used
   `get_transport_stack("default")`. The Slice 7.5 factory is additive —
   `register_default_plugins()` publishes both ids.
3. **CHANGELOG retroactive attribution** for v0.10.1 (PAL Slice 2/3). The
   code (`src/core/src/pal_default_registrars.cpp`,
   `src/core/include/nimrtc/core/plugin_id.hpp`) is unchanged at HEAD vs
   v0.10.1; only the docs catch up.

## Compatibility / upgrade notes

- **Public API**: byte-identical with v0.10.2. `git diff v0.10.2..v0.10.3
  -- 'src/engine/include/**'` shows zero lines.
- **ABI**: Not committed; experimental through v1.0.0. Pin to a specific
  commit.
- **Registry surface**: additive — `register_transport_stack()` now
  publishes `"webrtc-classic"` alongside the existing `"default"`. Any
  caller that explicitly requested `"default"` continues to work
  unchanged.
- **Engine**: unchanged. The engine still resolves ICE/DTLS/RTP/SCTP
  through its direct constructor path (Slice 7 + Slice 8 do not yet
  substitute the engine's backend ownership — that switch is a future
  Engine-Accepts-`ITransportStack*` change tracked in
  `transport-selection.md` §12.5.4). Slice 7.5's value is the
  `register_default_plugins()` path is now backed by a real factory.
- **No new third-party dependencies.** **No new tooling required.**
