## 1. Motivation

v0.10.3 is the final P1 patch — the patch train is sealed.
Three structural preconditions for P2 are now met:

1. **PAL Slice 1/2/3** (ADR-009) landed across v0.10.0–v0.10.3: engine
   resolves audio3a / codec / video_codec through `pal::*` seam; the
   `kDefaultRegistrars[]` table backs `register_all_default_plugins()`;
   `NIMRTC_PLUGIN_ID()` macro enables compile-time id validation.
   The assembly Profile library can now be backend-agnostic.
2. **ADR-010** (JSON Profile first-class): `profiles/*.json` are pinned
   as schema v1.0. The Profile library officialisation in v0.11.0 extends
   to all five profile variants.
3. **T-PAL Slice 7.5** (transport-selection.md §12.5): `WebRtcClassicStack`
   + `WebRtcClassicStackFactory` are registered; engine does not yet
   consume `ITransportStack*`, but the factory path and lifecycle are
   proven. Slice 4 (DTLS seam) and Slice 5 (SCTP seam) are the remaining
   Slices 4–8 path — both belong in v0.11.0.

v0.11.0 ships DataChannel basic interop (usrsctp), SFU relay,
PCM tap on WebRTC APM, and the assembly Profile library. P2 features
that require T-PAL Slice 6/7/8 (raw UDP bypass, Stack+Selector,
engine integration) are deferred to v0.11.x patches or v0.12.0.

## 5. Risk & mitigation

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| usrsctp cross-platform build (macOS / aarch64) fails | Medium | High (DC-1 blocked on those platforms) | Linux x86_64 first; gate macOS/aarch64 CI after Linux green; v0.11.0 release notes note platform coverage |
| PAL Slice 5 (usrsctp) introduces SCTP handshake regression on Chrome | Medium | High (DC interop is the headline feature) | Gate on `interop/` Chrome DataChannel suite before tag; TPAL-5 PR split by SCTP handshake / reliable / unreliable commits |
| PAL Slice 4 (DTLS factory) regresses existing DTLS tests | Low | High (DTLS is Tier 0) | Gate on `test_engine_plugin_loading` 7/7 + e2e Case D + `test_dtls_chrome_interop` |
| SFU relay benchmark (BENCH-1) shows lower pps than expected | Low | Low (benchmark is tooling; SFU itself is the feature) | Track trend, not absolute number; document methodology in `tools/benchmark/` |
| PAL Slice 5 is large (~800 LOC per Slice 5 post-mortem §12.2) and exceeds PR review capacity | Medium | Medium (delays DC-1) | Split Slice 5 follow-up PRs (usrsctp wiring / SCTP config extension / engine integration) into separate ≤ 200 LOC commits within one PR |
| RFC-1 stalls (no RFC topic reaches draft quality) | Low | Low (no code impact) | Track RFC-1 independently; v0.11.0 tag is not blocked if no RFC ships, but DISC-1 enables community RFC discussion |
| Profile library (PROFILE-1) surfaces missing PAL plugin ids | Low | Medium (discovered late, blocks PROFILE-1) | Pre-flight: enumerate all 5 profiles' plugin ids against `kDefaultRegistrars[]` before PROFILE-1 PR |

## 6. Release notes draft (skeleton)

To be expanded into `docs/plan/v0.11.0-release-notes.md` before tag.

```markdown
## v0.11.0 — Beta 前哨

This is the first minor to ship P2 content. All P1 work closed at
v0.10.3. **API still experimental / not for production through v1.0.**

### Highlights

- **DataChannel bidirectional interop (Chrome ↔ NimRTC)** — usrsctp
  integration via PAL Slice 5 (`ISctpSocket` → `UsrsctpSocket`). Supports
  reliable + unreliable, ordered + unordered. Chrome DevTools
  `chrome://webrtc-internals` shows NimRTC as a valid DataChannel peer.
  **Platform coverage: Linux x86_64 (first-class); macOS + aarch64
  TBD per CI expansion.**
- **In-process SFU relay** — new `nimrtc_sfu` module, bare-RTP pass-through
  with BUNDLE/rtcp-mux. Embeds in the host process; no separate worker.
  `sfu-relay` benchmark tool provides reproducible pps / Mbps figures.
- **PCM tap on WebRTC APM** — `set_pre_process_tap()` /
  `set_post_process_tap()` now have a WebRTC APM default implementation.
  Pre/post-3A audio frames are accessible for ASR / LLM pipelines.
- **AI Agent 接入 demo** — `demo-agent-gateway` demonstrates PCM tap →
  streaming ASR → LLM mock → response, using the `agent-gateway` Profile.
- **Assembly Profile library** — five profile variants are now first-class
  and loadable at runtime: `sfu` / `transport` / `agent` / `agent-gateway` /
  `sfu-agent`. PAL Slice 1/2/3 make all five backend-agnostic.
- **PAL Slice 4 (DTLS seam)** — `IDtlsSession` + `IDtlsSessionFactory`
  are the new seam. Engine uses `factory->create(config)` instead of
  direct `new DtlsSessionWolfSSL`. Public API unchanged.
- **GitHub Discussions** — community now has a Discussions space alongside
  issues.

### Known limitations

- usrsctp on macOS + aarch64 is experimental; Linux x86_64 is the
  first-class platform for DataChannel in v0.11.0.
- T-PAL Slice 6 (raw UDP bypass for ultra-low-latency control) is
  deferred to v0.11.x patch.
- 国密后端 (SM2/SM4) remains P4 / Enterprise — not in v0.11.0.
```

## 7. Rollback / abort criteria

If at any point before tag cut we discover:

- usrsctp handshake fails with Chrome on Linux x86_64 after two
  debugging iterations → cut **v0.11.0-rc1** with DataChannel feature
  flagged experimental in release notes; full interop to v0.11.x.
- PAL Slice 4 regresses any DTLS test (Tier 0 interop) → revert
  `engine.cpp` factory usage back to direct construction; land Slice 4
  as v0.11.x patch after root cause found.
- SFU relay benchmark reveals fundamental architectural conflict with
  BWE/JB modules → defer SFU-1 to v0.11.x; continue without SFU-1 in
  v0.11.0 tag (DataChannel + Profile library are still sufficient).
