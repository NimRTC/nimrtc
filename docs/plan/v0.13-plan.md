## 1. Motivation

v0.12.0 is the **last "Tech Preview" minor that ships feature work**.
The remaining blockers for v1.0.0 (per `v1.0-plan.md` §1) are
**stability commitment + the data plane (DC-1)**. v0.13.0 is the
cycle that opens the v1.0.0 work by landing the **mechanical
foundation** that v0.14.x (v1.0.0-alpha.2 + v1.0.0-beta.1) and v1.0.0
itself will build on.

Three concurrent tracks converge in v0.13.0:

1. **API stability framework** (per `v1.0-plan.md` §2.1.1 P0
   API-VERSION + API-FREEZE + ADR-015): the `NIMRTC_API_VERSION`
   macro set, the `NIMRTC_API_STABLE` / `NIMRTC_API_UNSTABLE` /
   `NIMRTC_API_DEPRECATED` markers, the deprecation policy ADR,
   and the public-header classification sentinel test. **Already
   landed as `6cea40f` (2026-10-14)**; the bulk classification
   sweep (85 of 89 public headers) is a v1.0.0-alpha.2 follow-up
   that **ships in v0.13.0 alongside alpha.1** per the §12.2
   pre-release split, so v0.13.0 closes the alpha.1 DoD gates.
2. **P1 UAF-DTLS weak_ptr migration** (per
   `docs/plan/p1-uaf-dtls-investigation.md`): the v0.12.0 P0
   `is_open()` API-surface guards (Findings #1, #2) are
   defence-in-depth, not type-system enforcement. v0.13.0
   replaces `Impl::dtls` and `Impl::datachannel_transport_cookie`
   with `std::weak_ptr<IDtlsSession>`, making every use site a
   compile-time checkable `.lock()` that **auto-expires on
   `close()`**. **Already landed as 5 commits
   (`9f4956b` + `313b40c` + `d0665aa` + `e79a1eb` + `5eb65fa`;
   the WARN-cast function lives inside the same `5eb65fa` Slice 1.5
   commit, not as a separate SHA in HEAD)**.
3. **PAL Slice 1.5 follow-up** (per ADR-009 § "Slice 1.5
   follow-up (v0.12.0)" — staged into v0.13.0 because v0.12.0
   was tagged before Slice 1.5 landed): the `pal::MakePluginOpts`
   named-arguments struct, the C++20 `auto Resolver` template
   parameter on `pal::make_plugin`, and the migration of all 9
   `engine.cpp` plugin-load call sites. **In flight as M files
   in the working tree** (commit pending at v0.13.0 tag-prep).

Plus a **fourth catch-all track** for the v0.12.x patch follow-ups
that v0.12.0 explicitly deferred (per `v0.12.0-release-notes.md`
"What's NOT in v0.12.0") and that are small enough to ride the
v0.13.0 train:

4. **v0.12.x patch follow-ups** — OHAudio HAL adapter
   implementation (Stage 4 of `openharmony-support.md`);
   `max_p99_ms` budget enforcement (StrategyValidator per
   `transport-strategies.md` §6 #4); `cross-network-peer` naming
   review (per `transport-strategies.md` §6 #1); §5.3 rule 2
   media-plane production hardening (reliable media over ARQ
   + FEC + codec negotiation, per `transport-selection.md`).

> **Why v0.13.0 = v1.0.0-alpha.1 and not just v0.13.0**: the
> `v1.0-plan.md` §8 + §12.2 pre-release split makes this explicit.
> v0.13.x is the **alpha.1 phase**; the semver pre-release tag is
> `v1.0.0-alpha.1` and the **NIMRTC_API_VERSION_PRE_RELEASE** macro
> is `"alpha.1"`. The marketing version ("v0.13.0") stays anchored
> to the v0.x line because the public surface is still labelled
> "Tech Preview" — the banner does not flip until v1.0.0 final.
> v0.14.x = v1.0.0-alpha.2 + v1.0.0-beta.1, v1.0.0 = v1.0.0 final.
> **There is no separate v0.13.0 → v1.0.0-alpha.1 migration PR**;
> the v0.13.0 tag cut is itself the alpha.1 tag cut, with the
> `v1.0.0-alpha.1` annotation appended to the tag message body.

## 7. Rollback / abort criteria

- **`test_api_classification.every_header_has_at_least_one_marker`
  cannot flip to PASS in v0.13.0** (i.e. the bulk 85-header
  sweep surfaces an unresolvable "experimental but load-bearing"
  class of symbol) → per ADR-015 §Consequences, either (a)
  stabilise the symbols in v0.14.x, or (b) move them to an
  `-internal/` namespace pre-v1.0.0. The classification sweep
  PR queue is split into dependency-ordered batches so the
  failure surface is bounded per PR. If a batch fails to
  converge, the v0.13.0 tag cut is held; v0.13.x continues
  the sweep.
- **PAL Slice 1.5 `auto Resolver` template parameter breaks
  the `pal::make_plugin` callers** → the 27 + 15 + 13 subtest
  matrix in ADR-009 is the source of truth; if any subtest
  fails, revert Slice 1.5 to v0.12.0-post1 baseline, defer to
  v0.14.x. v0.13.0 tag cuts without Slice 1.5; only the API
  stability framework + weak_ptr migration land.
- **Weak_ptr migration `tests/test_engine_plugin_loading.v013_dtls_weak_expires_after_close`
  fails on Linux-gcc or macOS-clang (it is Windows-MSVC-only
  at v0.13.0 plan open)** → the 4-platform CI is Gate #8; if
  CI is red on any platform, hold the tag cut and bisect.
  The weak_ptr migration is the only platform-portable
  concern in the v0.13.0 work; if it is platform-broken, the
  whole v0.13.0 is held.
- **The `v0.13.0` ↔ `v1.0.0-alpha.1` aliasing creates a
  release-process confusion (e.g. GitHub Release UI requires
  one tag per release; CI release workflow fails on dual
  names)** → the `v0.13.0` tag is the **canonical** Git tag;
  the `v1.0.0-alpha.1` name is in the CHANGELOG header and
  the tag message body only. If GitHub rejects the alias,
  add a `v1.0.0-alpha.1` annotated tag pointing at the same
  commit (2 tags for 1 commit; this is the §5 risk #6 escape
  hatch).
- **OHAUDIO-IMPL / P99-ENFORCE / CN-NAMING scope creep into
  v0.13.0** → all three are slip-or-land per §2.1.4; v0.13.0
  tag cuts without them. They are documented as "deferred to
  v0.13.x" in the release notes.
- **Pre-1.0 decision window items (SFU-1 / DC-3 / BENCH-1)
