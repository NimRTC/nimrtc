## 1. Motivation

The `v0.x` line closes with the v0.12.0 release (per the in-progress
`docs/plan/v0.12.0-release-notes.md`). All P1 + most P2 work is
shipped. The remaining blockers for the v1.0.0 "stable" label are
clearly enumerated across the planning documents and amount to three
classes of work:

1. **Data plane Chrome interop (DC-1, the headline P2 deferred item)**
   — `docs/plan/v0.11-plan.md` §2.2 + §10 explicitly deferred the
   SCTP-over-DTLS path; v1.0.0 lands the **WebTransport over QUIC**
   re-design and ships a working `NimRTC ↔ Chrome DataChannel`
   interop. This is the v1.0.0 headline gate.
2. **API stability commitment** — every `v0.x` release note repeats
   "API still experimental / not for production through v1.0.0".
   v1.0.0 drops that banner, which means (a) the public header
   surface is frozen, (b) a deprecation policy is in place, and
   (c) every public symbol carries a stability class
   (`NIMRTC_API_STABLE` / `NIMRTC_API_UNSTABLE`).
3. **Pre-1.0 decision window items** (per
   `docs/plan/v0.11-plan.md` §2.2) — `SFU-1 / DC-3 / BENCH-1` are
   either landed in v1.0.0 or pushed to v1.x.0. The decision is
   made during v0.13.x or v0.14.x (whichever cycle the upstream
   signals it).

> **What v1.0.0 is NOT**: it is NOT a feature dump. The v0.12.0
> baseline already ships the GMSSL TLCP backend, the OHOS Stage 0
> toolchain, the 5 named transport strategies, the Profile v1.1
> schema, PCM tap, the Profile library, and the AI Agent demo.
> v1.0.0's contribution is **stability + the missing data plane**
> — not new features.

If at any point before tag cut we discover:

- Chrome e2e Case E regresses → hold the tag cut; bisect between
  v0.14.0 and HEAD; the `interop/chrome` harness is the source
  of truth.
- ADR-014 vendor choice forces a problematic trade-off (license,
  FFI surface, single-platform lock-in) → reopen ADR-014;
  the second choice is quiche (C API, MIT-licensed via the
  C bindings; or Rust CFFI which is the deal-breaker).

  but load-bearing" symbol → either stabilise it in v0.14.x or
  move it to a `-internal/` namespace pre-1.0.0. **Do not**
  ship v1.0.0 with undocumented experimental symbols in the

  BENCH-1 to v1.1.0 (per the §2.2 escape hatch); ship v1.0.0
  with the **stable API + DC-1 land** baseline.

## 10. WebTransport / QUIC vendor spike (DC-1 prerequisite)

> **Status: placeholder.** The vendor decision lands in
> **ADR-014** at v0.13.0 tag-prep. This section captures the
> evaluation framework so the v0.13.x PR can land on a
> defensible decision.

### 10.1 Candidate evaluation

| Candidate | License | FFI surface | Windows | Linux | macOS | aarch64 | Cross-platform CI path |
|---|---|---|---|---|---|---|---|
| **msquic** (Microsoft) | MIT | C / C++ native | ✅ first-class (kernel QUIC) | ✅ (kernel + userspace) | ✅ (userspace) | ✅ (Linux aarch64) | Well-trodden; same as .NET / Kestrel |
| **quiche** (Cloudflare) | BSD-2 | C API (via `quiche.h`) + Rust crate (CFFI) | ⚠️ userspace only | ✅ | ✅ | ✅ | Quiche's C API is the path; the Rust crate is CFFI (deal-breaker for the `src/plugins/` header-only invariant) |
| **Google libquic** | BSD | C++ | ⚠️ proprietary build infra | ⚠️ | ⚠️ | ⚠️ | License OK; build infra is a problem; not maintained outside Chromium |
| **Custom** | n/a | C++ | ❌ | ❌ | ❌ | ❌ | Out of scope (multi-year project) |

### 10.2 Decision criteria

1. **License**: MIT / BSD-2 / Apache-2 only (no GPL, no SSPL).
2. **No Rust / no CFFI**: preserve the `src/plugins/` header-only
   invariant; no FFI surface that violates it.
3. **Cross-platform CI green**: windows-2022 + linux-gcc + macos-clang
   + linux-aarch64.
4. **Windows is first-class**: msquic's kernel-mode QUIC support is
   the differentiator; quiche is userspace-only on Windows.
5. **Active maintenance**: last commit within 6 months of v0.13.0
   tag cut.

### 10.3 Provisional decision (pending spike)

**msquic** — MIT-licensed, native C / C++ API, Windows-first,
cross-platform CI green, no FFI / no Rust. The spike must
verify items 1-5 above; if any fails, fall back to **quiche**
(BSD-2, C API, userspace only) with the Windows story
documented as a v1.1.0 follow-up.

### 10.4 Seam surface (DC-1)

```cpp
// src/web_transport/include/nimrtc/web_transport/web_transport_session_iface.hpp
namespace nimrtc::web_transport {

class IWebTransportSession {
public:
    virtual ~IWebTransportSession() = default;

    // Bidirectional stream: open + send + recv.
    // Replaces `ISctpSocket::send_*` / `set_on_recv` for the
    // WebTransport / QUIC data plane.
    virtual std::unique_ptr<IBidirectionalStream>
        open_bidi_stream() = 0;

    // Unidirectional stream: send-only (one-way).
    virtual std::unique_ptr<IUnidirectionalStream>
        open_uni_stream() = 0;

    // QUIC DATAGRAM frame: unreliable, message-oriented.
    // Maps to PR-SCTP "unreliable" + the WebTransport datagram
    // duplex mode.
    virtual void send_datagram(span<const std::uint8_t> payload) = 0;
    virtual void set_on_datagram(OnDatagramCb cb) = 0;

    // Lifecycle.
    virtual void close() noexcept = 0;
    virtual State state() const noexcept = 0;
};

class IWebTransportSessionFactory {
public:
    virtual ~IWebTransportSessionFactory() = default;
    virtual std::string_view id() const noexcept = 0;
    virtual std::unique_ptr<IWebTransportSession>
        create(const WebTransportConfig& cfg) = 0;
};

} // namespace nimrtc::web_transport
```

The `core::PluginRegistry` gets a new typed slot
`register_web_transport()` (parallel to the Slice 8 DTLS / SCTP
slots). The engine's `Impl::datachannel` field swaps from
`ISctpSocket*` (legacy) to `IWebTransportSession*` when the
`EngineConfig::datachannel_backend = "web_transport"` (a new
optional field, default `"web_transport"` post-v1.0.0, `"sctp"`
for v0.x compatibility).

## 12. v1.0 预发布版本拆分 (Pre-release split)

> **Status: opening.** v1.0.0 是 7-10 个月的工程，单 tag 风险过高。
> 按 semver 预发布约定拆成 `alpha.N → beta.N → rc.N → v1.0.0` 序列，
> 每版有明确范围 + 进入条件 + 退出条件。本节定义拆分方案；具体的
> alpha/beta/rc 计划文件在对应阶段开 tag 前再细化。

### 12.1 拆分原则

1. **API 稳定性反向锁**：v1.0.0-alpha 阶段**可以**改公共头；
   v1.0.0-beta 阶段**冻结**公共头（仅 additive）；v1.0.0-rc 阶段
   **只修 bug**（no public API change at all）。
2. **Banner 升级节奏**：
   - alpha: "v1.0.0-alpha.N (Tech Preview — <阶段名>)"
   - beta: "v1.0.0-beta.N (Beta — <阶段名>)"
   - rc: "v1.0.0-rc.N (Release Candidate)"
   - final: "v1.0.0 (Stable)"
3. **4-平台 CI 必须 green**：每个预发布版本 tag 前，4-平台 CI
   (windows + linux-gcc + macos-clang + linux-aarch64) 必须
   全部 green。`NIMRTC_SKIP_CASE_*` 仅 alpha 阶段允许；beta 起
   必须 0 escape hatch。
4. **每版带回归 test 增量**：每个 pre-release 都附带新的
   `tests/test_*.cpp` 子测试；回归 test 只能加不能减。

### 12.2 版本序列
