# v1.0.0 — Stable

> **Status: Stable.** First stable release of NimRTC.
> The "experimental through v1.0.0" banner on every `v0.x` note is dropped.
> Public API is frozen per [ADR-015](../adr/ADR-015-api-stability-policy.md);
> breaking changes require a MINOR/MAJOR bump.
> DoD: `docs/plan/v1.0-plan.md` §3 + §12.3.6.

## Highlights

- **Chrome ↔ NimRTC DataChannel bidirectional interop (DC-1)** over
  WebTransport / QUIC — Case E E1–E6 PASS via
  `tests/chrome_interop_harness/run_webtransport_harness.py` +
  `interop/chrome/test_chrome_webtransport.html` against
  `examples/demo-wtserver` (datagram + bidi-stream echo).
  `EngineConfig::datachannel_backend` defaults to `"web_transport"`;
  explicit `"sctp"` keeps the legacy path.
- **API stability commitment** — every public symbol under `nimrtc/*`
  carries `NIMRTC_API_STABLE` / `NIMRTC_API_UNSTABLE` /
  `NIMRTC_API_DEPRECATED` (102 headers, `Missing: 0` via
  `scripts/api_freeze_scan.js`); `NIMRTC_API_VERSION` = 10000,
  `NIMRTC_API_VERSION_PRE_RELEASE` = `""`.
- **L1 strict-priority scheduling across the DC plane (DC-2)** —
  `src/modules/sched/tests/test_sched_priority_dc.cpp` 17/17.
- **Vendor drift is a hard CI gate** — `tools/check_vendor.py`
  red-blocks merges in `ci.yml` (×4) + `interop.yml` (×2); 9/9 match.

## Notes

- `test_datachannel_engine` 5/5 stays green (in-process regression).
- `test_sctp_usrsctp` 4/4 stays green; usrsctp stays `@deprecated`
  in tree through v1.1.x, removal at v1.2.0.
- aarch64 release bundle is best-effort: CI leg is a hard gate,
  release leg is `continue-on-error` until its first observed green run.
- Per-platform 3A variance: release bundles ship real WebRTC APM 3A
  where the meson prebuild succeeds, stub 3A otherwise; never silent.

## What v1.0.0 is NOT

- Not a feature dump: payload is stability + the missing data plane
  (DC-1/DC-2), not new protocols (no SFrame / no MLS).
- SFU-1 / DC-3 / BENCH-1 stay off the v1.0.x critical path
  (§7 = NO, closed 2026-10-19, BDFL: SFU is not a project core goal).
- usrsctp removal is v1.2.0, not v1.0.0.
