## 1. Goal

`v1.1.0` is a quality + packaging release. It does not add protocols. It makes `v1.0.x`
verifiable and consumable:

- Anyone can reproduce latency/jitter/throughput numbers from `build/e2e/`.
- Timeline seam (ADR-017 Decisions 3–4) is documented as landed: fitted slope + real skew.
- Release matrix is hard green on all four platforms (W3 + W5 closed).
- Downloaded bundles are consumable: `cmake --install` yields `include/` + `lib/` +
  `lib/cmake/NimRTC/`, and `find_package(NimRTC)` resolves without a source build
  (fixes the `v1.0.2` known issue where bundles shipped only the vendored third-party stack).

Out of scope: SFU-1 / DC-3 / BENCH-1 SFU parts, new codecs, mobile bindings,
production deployment guarantees.

Local signing toolchain (verified 2026-11-03): GnuPG 2.4.8 is installed at
`C:\Program Files\GnuPG\bin\gpg.exe`, and the release key
`114154CFEC3F5EE5A8D2D313BEACFBB55871CC06` (ed25519, uid "NimRTC Release")
is present in `~/.gnupg` with its secret key. `git` is configured repo-locally
with `gpg.format=openpgp`, `user.signingkey=114154CF...`, `commit.gpgsign=true`
and `tag.gpgsign=true`. A scratch-repo rehearsal produced a signed commit and a
signed tag whose `git cat-file tag` output carries a `BEGIN PGP SIGNATURE`
block and whose `git tag -v` reports "Good signature". The public key exported
from this keyring is byte-identical to the `nimrtc-signing-key.asc` asset
shipped with `v1.0.2`, so the key published on the keyservers is the key that
will sign `v1.1.0`. C4 is therefore unblocked except for cutting the tag
itself, which still waits on C5's soak evidence and the Track A/B/D gates.

C6 blocker (2026-11-03): uploading the key needs either the web UI at
`https://github.com/settings/keys` or a token carrying `admin:gpg_key`, and
neither is reachable from this host right now — `github.com` itself times out
on GET and POST (`api.github.com` still answers), and `gh auth refresh -s
admin:gpg_key` cannot complete its device flow because the OAuth token
exchange POST to `github.com` times out. The `gho_` token in the gh keyring
carries only `gist, read:org, repo, workflow`; the `github_pat_` token in
`GH_TOKEN` answers 401 "Bad credentials". C6 remains a web-UI step for a
network path that can reach `github.com`.

Audit note (2026-11-03, v1.0.1 post-mortem): the three v1.0.1 defects (WebTransport
ALPN mismatch, 822 MB Windows bundle, unpublished signing key) were all confirmed and
are fixed in `v1.0.2`; the v1.0.1 release body now carries the "Known issues" section
pointing at `v1.0.2`. C4/C5/C6 are the process-level leftovers that `v1.0.1`/`v1.0.2`
could not close retroactively.

does not resolve (see `RELEASING.md` §4). D lands in `v1.1.0` directly:

| D2 | `NimRTCConfig.cmake` + version file | `lib/cmake/NimRTC/NimRTCConfig{,Version}.cmake` via `CMakePackageConfigHelpers` (`SameMajorVersion`); version tracks `project(VERSION)` |
| D3 | Bundle layout parity + downstream proof | All four legs pack `include/` + `lib/` + `lib/cmake/NimRTC/` staging-relative; minimal `find_package(NimRTC 1.1 REQUIRED)` consumer links `nimrtc::engine` on Linux + Windows; 64 MB guard + SBOM/signing unchanged |
| D4 | WebRTC APM prebuilt ships with the bundle | The Meson-built APM archive + its abseil archives are installed to `<prefix>/lib/webrtc_apm/` with the link-order manifest, and the installed `NimRTCConfig.cmake` chains them in that order — a consumer linking `nimrtc::engine` resolves `webrtc::` / `absl::` symbols instead of failing to link |
