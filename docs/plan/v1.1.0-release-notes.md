# v1.1.0 — Release candidate

> **Status: Release candidate.** The source version is `1.1.0`
> (`project(VERSION)` in `CMakeLists.txt`, `NIMRTC_API_VERSION` = 10100,
> `NIMRTC_API_VERSION_PRE_RELEASE` = `""`). The published stable cut is
> still `v1.0.2`; the `v1.1.0` tag is cut when the remaining
> release-hardening gates close (the 7-day soak evidence, the signed
> annotated tag, and the release-key upload to the GitHub account GPG
> list — see "Gates still open").
> Plan of record: `docs/plan/v1.1-plan.md`. Version ladder: §5.6 of that
> plan — `v1.1.0` is the only feature-bearing release of the `v1.1` line,
> `v1.1.x` carries fixes only, new behaviour starts at `v1.2.0`.

## Highlights

- **The RTCP feedback loop is closed end to end (Track Q3).** The engine
  consumes receiver reports, drives bandwidth estimation, and feeds the
  result back into the pacing path; the video jitter buffer no longer
  drops complete frames, and the shared adaptive playout strategy is used
  by the audio and the video jitter buffers alike.
- **A reproducible weak-network baseline facility (Track Q4).** Two paths
  measure the same three tiers (5% loss, 20 ms base + 0–100 ms jitter,
  1 Mbps cap) over a 1200 B payload: a portable in-process userspace
  shaper (`tools/benchmark_weaknet.py`) and a real kernel `netem` path
  (`tools/benchmark_weaknet_netem.sh`). Both account in wire bytes and
  keep the offered load at 90% of the capacity, so the numbers are
  comparable instead of measuring the sender's own queue.
- **GMSSL is a real git submodule, default OFF (Track X1).** GmSSL v3
  enters as `src/third_party/gmssl`, built only when
  `NIMRTC_ENABLE_DTLS_GMSSL=ON`, so the default build's size, build time
  and artefact set are unchanged. Vendoring was gated on verifying the
  pinned commit's LICENSE text and recording it in `vendor.json`; the
  acceptance criteria include a Windows/MSVC compile, because GmSSL v3 is
  rougher there than on Linux.
- **The SRTP backend seam landed (Track X2); SM4-GCM stays v1.2+.** libsrtp
  is now reached through `ISrtpSessionBackend`. The SM4-GCM SRTP
  implementation is deliberately deferred: it would require re-deriving
  RFC 3711's KDF with SM3 as the PRF, i.e. self-built security-critical
  crypto, which the project's D1 constraint forbids.
- **The installed bundle is a usable downstream artefact (Track D).**
  Per-module `install()` rules and a generated `NimRTCConfig.cmake` land
  in the bundle, the WebRTC APM prebuilt ships with it, and the shared
  `jb_strategy` module is no longer missing from the installed set.
- **Engine-side groundwork for the video pipeline.** `engine.cpp` is split
  into five responsibility translation units, the `ref_frame` timeline map
  is exposed to the host, and the video counters are wired into the
  statistics surface. The engine exposes the seams; the pipeline rewrite
  itself is v1.2.0–v1.4.0 (`docs/plan/video-pipeline-v2-plan.md`).
- **Vendor hygiene that the manifest can prove.** libsrtp is a real
  submodule (gitlink) instead of ~2400 checked-in files, and
  `tools/check_vendor.py` now distinguishes a verified submodule from a
  vendored tree instead of counting both as "vendored".
- **The public wording matches reality.** The `cloudgame` Profile is
  documented as a long-term candidate that is *not* in the shipped
  Profile set (it never was), and the GM/T claim is narrowed to
  "DTLS/TLCP covered, SRTP still on the international suites" — a
  compliance statement that had to be corrected for regulated customers.
- **Release tooling that can be audited.** Tag-signature verification, an
  offline release-signature verifier, and a 7-day soak evidence collector
  (`tools/run_soak.py`) that appends its records instead of overwriting
  them.

## Fixes worth calling out

- **The GMSSL TLCP backend corrupted the heap on every `open()`.** The
  `TLS_CTX` / `TLS_CONNECT` buffers were sized from stale measurements of
  an older GmSSL (128 KiB / 256 KiB) while the real structs are ~201 KiB /
  ~189 KiB, so `tls_ctx_init()`'s `memset` ran past the end of the
  allocation and `test_dtls_gmssl_tlcp` died with a SEGV. The buffers are
  now sized from the real `sizeof()` plus a margin, with a compile-time
  `#error` guard on the GmSSL feature macros that decide the struct
  layout.
- **The vendored Opus library was built against a different C runtime.**
  The target property was named `CMAKE_MSVC_RUNTIME_LIBRARY` instead of
  `MSVC_RUNTIME_LIBRARY`, so the override was a silent no-op and Debug
  builds linked two CRT heaps — the engine tests that touch the Opus path
  died with an access violation before `main()` printed a line. The
  property name is fixed and the compile-flag rewrite maps `/MTd` and
  `/MT` to `/MD`.
- **Commit and tag signatures showed up as unverified on GitHub.** The
  signing key's only user ID was a Gitee noreply address that no GitHub
  account owns, so GitHub answered `no_user`. The key's user ID is now
  the account address of `NimRTC`; the fingerprint is unchanged, so
  signatures made before the rename still verify.
- **The video jitter buffer silently dropped complete frames**, and the
  3A stage did not behave as its own contract said — both are covered by
  regression tests now.
- **The installed bundle was missing the shared jitter-buffer strategy**,
  so a downstream build that linked the installed tree failed at link
  time.

## Notes

- The suite is green with the fixes above: 697 tests, 0 failures
  (CHANGELOG `## [1.1.0]`), and `ctest` 629/629 on Windows 10 x86_64 after
  the libsrtp submodule conversion on 2026-11-03.
- W3 (Windows WebRTC APM prebuild `continue-on-error`) and W5
  (`build-linux-aarch64` soft gate) are closed — 2026-11-06 and
  2026-11-05 respectively. `docs/plan/ci-workarounds.md` W3/W5 remain the
  source of truth.
- The acceptance runner drives the real-browser interop cases: Case D
  (NimRTC ↔ Chrome, full audio path: ICE + DTLS + SRTP + Opus RTP) and
  Case E (DTLS-only, wolfSSL ↔ BoringSSL). Both verdicts are read from
  fresh evidence — a stale results file can no longer decide a case.
- Per-platform 3A variance stays explicit: bundles ship the real WebRTC
  APM 3A where the meson prebuild succeeds and the built-in stub 3A
  otherwise. It is never silent.
- The API surface is additive only; `scripts/check-release-freeze.sh`
  passes 6/6.

## What v1.1.0 is NOT

- Not a new protocol release: no SFrame, no MLS, no mandatory DTLS 1.3.
- **usrsctp removal is `v1.2.0`**, not v1.1.0; the usrsctp backend stays
  `@deprecated` in tree through the v1.1 line.
- **SM4-GCM SRTP is `v1.2.0+`** — this release lands the SRTP backend
  seam only.
- **The `cloudgame` Profile is not shipped** and does not enter the
  official set (BDFL, 2026-11-04).
- **The audio pipeline rewrite is not in this release.** Its
  specification is complete (`docs/plan/audio-pipeline-spec.md`), but the
  implementation belongs to the `v1.2.0` line.
- **The video pipeline rewrite is not in this release.** Its stages span
  `v1.2.0`–`v1.4.0` (`docs/plan/video-pipeline-v2-plan.md`).
- SFU-1 / DC-3 / BENCH-1 stay off the critical path
  (`docs/plan/v1.0-plan.md` §7 = NO, 2026-10-19).
