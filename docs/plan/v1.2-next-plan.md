## 1. Why this plan exists

`main` currently contains more *implemented* than *proven* capability. The v1.2.0
body — audio pipeline P0+P1, video pipeline Part B (feedback/BWE/pacing/ABR),
session capability, DataChannel, and remote-desktop M1–M4 — is merged, and the
Windows test suite is green. What is missing is the second half of the claim:
cross-platform compilation proof, activation of paths that are written but not
enabled (AEC, DXGI zero-copy, TURN/TLS), and the observability surface
(`getStats`) that a user needs in order to trust the engine at all.

Tracks E and S therefore close the v1.2.0 promise. Tracks Q and C define the two
following releases, each of which strengthens a dimension the current engine is
weakest in — respectively *resilience* and *reachability*.

**Sequencing note:** E2 before E1 — the manifest must be generated on a build that
at least *compiles* on all three platforms, otherwise the baseline encodes a
Windows-only view of the surface.  **Done in that order** (#71/#72, then the
manifest), and the manifest agrees with the count-based check on the same 191
headers.

**E2 — what landed.** The Linux CI leg now installs the leaf-adapter dev packages
and *asserts* that every adapter leaf was compiled in, rather than letting a
missing package silently skip a source file. Two rounds:

- **PR #71** — the X11, XFixes, PipeWire and EGL leaves. The first CI run of
  that PR failed on the `NIMRTC_VIDEO_SINK_HAS_EGL=1` assertion, which was
  exactly the point: the runner image ships no EGL dev package, so the
  assertion caught a path that would otherwise have been skipped.
- **PR #72** — the Wayland leaves (`wayland-client`, `wayland-egl`,
  `xdg-shell`, `linux-dmabuf`). Asserting these exposed that **the Wayland
  renderer had never been compiled on any build host**: `wayland-protocols`
  ships the protocol XML, but the CMake lookup searched for the *generated*
  header, so it never succeeded and ~20 branches of `egl_renderer.cpp` were
  dead code. Behind them were four real defects (a `wl_shm_pool_create_buffer`
  call with three arguments instead of six, whose `wl_buffer*` result was then
  used as a raw pixel buffer; a DMA-BUF import calling a protocol API that
  does not exist; two non-existent Wayland requests; a missing listener member).
  All four are fixed and the path now compiles with all six optional leaves
  enabled.
- **PR #76** — the input-injection leaves (XTest, uinput). Asserting these
  exposed that **the XTest injection backend had never been compiled on any
  build host**: `libxtst-dev` was not in the CI package list, so
  `NIMRTC_HAS_XTEST=1` was never defined and roughly 200 lines of
  `linux_input.cpp` — the whole X11 branch of the injector — were dead code.
  Compiling it surfaced two real defects: `XTestFakeRelativeMotionEvent`
  was called with `nullptr` as its fourth argument, but that parameter is
  the event *delay* (an `unsigned long` timestamp), not a pointer; and the
  module linked `libXtst` but not `libX11`, so the `XOpenDisplay` /
  `XFlush` / `XCloseDisplay` calls it makes through the extension were
  undefined at link time.  Both are fixed, and both the XTest and the
  uinput backends are now asserted in CI.
- **PR #78 — the Wayland sink presented nothing.**  E2 proved the Wayland
  leaves *compile*; running the sink against a headless Weston showed that
  neither presentation path had ever *presented* a frame.
  `init_egl()` left the EGL context bound on the `open()` thread, so the
  presenter thread's `eglMakeCurrent()` failed with `EGL_BAD_ACCESS` on every
  frame; `init_wayland()` committed the first buffer before the `xdg_surface`
  had been configured, which Weston treats as a protocol error and kills the
  client; and `draw_with_egl()` counted a failed `eglSwapBuffers()` as a
  presented frame.  All three are fixed; both the EGL and the `wl_shm` paths
  now present 1280x720 and letterboxed 320x180 streams under headless Weston
  with no protocol errors.

macOS (ScreenCaptureKit, Metal) is covered by the existing `macos-clang / arm64`
leg, which compiles the whole tree including the Objective-C++ renderer.

**E1 — what landed.** The API surface is now pinned by a *set*, not a *count*.

`tests/test_api_classification.cpp::total_header_count_matches_baseline` asserted
that the number of public headers equalled a baseline constant.  A count cannot
tell a swap from a change: deleting `a.hpp` and adding `b.hpp` in one PR leaves
the count untouched, so CI stayed green while the public surface had moved.
ADR-015 calls that surface a contract, and a contract needs the actual list.

`docs/api/public_headers.manifest` is that list — 191 paths, sorted, one per
line, `/`-separated, relative to the repo root.  `scripts/check_api_manifest.py`
compares it against the tree and names both sides of a drift (the headers that
appeared, the ones that went away).  It is wired into all four platform legs of
`ci.yml` and into `ci-fast`.

The manifest and the existing count check agree on the selection rule (the same
191 headers), so the manifest is a strict refinement of the old gate rather than
a second, differently-scoped surface.

**Consequence for Track S.** The freeze is now a fact, not a future event, so
Track S lands *after* it — see the D-N6 sequencing note under Track S.  Every
public symbol Track S adds is an explicit, reviewed manifest bump.

**E7 — what landed, and why the row was smaller than it read.**  The plan
first wrote E7 as "write an in-tree SCTP stack, then delete the vendor tree",
which would have made it the schedule driver of M0.  That reading was wrong,
and the correction is the interesting part of this row.

The SCTP data plane was **already** retired from the *public* selector in
v1.2.0 (WP-A / DEC-4 = A1): `datachannel_backend = "sctp"` is rejected by
`engine_transport.cpp` with a hard error, and the default `sctp_socket_name`
is `"stub"`.  `nimrtc::sctp::register_default_plugins()` has published only
the `"stub"` factory since v0.11.0 — the `"usrsctp"` factory was *never* in
the registry on `main`.  So there was no in-tree SCTP stack to write: what
remained was a **deletion** of unreachable code that the build still paid for
on every platform.

What the change removed:

- `src/third_party/usrsctp/` — 269 files, ~5.5 MB — and the
  `nimrtc_vendor_usrsctp` target (plus its `install()` and
  `find_library()` entries in `NimRTCInstall.cmake` / `NimRTCConfig.cmake.in`).
- `usrsctp_socket.cpp` / `usrsctp_factory.cpp` and their two `@deprecated`
  public headers.
- `tests/test_sctp_usrsctp.cpp` — the in-process loopback regression.  It
  only ever ran on Linux (the `usrsctp_connect()` handshake never completed
  on Windows or macOS, so those platforms skipped it), and the backend it
  exercised no longer exists.
- `SctpDataChannel`'s production constructor's `get_sctp_socket("usrsctp")`
  lookup, replaced by `"stub"` — the only registered SCTP id.  The channel is
  now a well-defined "no data plane" channel (every send returns
  `kErrNotReady`) rather than a null-pointer one.

What it deliberately did **not** change:

- The `ISctpSocket` / `ISctpSocketFactory` seam.  The production data plane
  is WebTransport over QUIC (msquic), which never went through this seam.
- The `"sctp"` DataChannel factory's registration: it stays in the registry
  as the in-tree reference implementation for the DCEP codec and the PR-SCTP
  semantics.  What is retired is the *public selector*, not the backend.

The public header set shrinks from **191 to 189**.  Per D-N6 the manifest and
the count-based gate are regenerated in the same PR, and the PR names the two
headers it removes.

**Sequencing (D-N6).** Track S lands **after** the E1 manifest freeze, not
before it.  The manifest gate now exists to *catch* an undeclared public
surface, so freezing it before Track S adds public fields would either block
the work or train people to regenerate the manifest without thinking.  Instead:

- Every Track S row that adds a public symbol (S1's `snapshot_time_us` /
  `StatsDelta`, S2's inbound entry type, S5's candidate-pair entry) **must**
  come with an explicit `scripts/check_api_manifest.py --write` regeneration in
  the same PR, and the PR description must name the symbols it adds.
- The regeneration is not free: it is the *review surface*.  A manifest diff
  that adds a public type is a contract change, and the reviewer reads it as
  such — which is exactly the property the old count-based gate lacked.
- This supersedes the earlier sequencing note ("Track S consumes Track E's API
  baseline, so any new public field lands before E1 freezes the manifest").

### Track Q — Resilience and quality line (v1.3.0)

## 5. Definition of done (per track)

- **Track E** — every row in §3 Track E has its "done when" satisfied *and* recorded
  in the repo (manifest file, CI config, interop doc, benchmark output). Verbal
  evidence does not count.
- **Track S** — every stat field is documented, has a unit test, and appears in the
  sample app's output. The manifest freeze has already happened (D-N6), so the
  rule is the mirror image of the old one: every public field added *after* the
  freeze is an **additive, reviewed baseline bump** — the same PR carries the
  `check_api_manifest.py --write` regeneration, and the PR names the symbols it
  adds. A silent drift is a failed DoD even when CI is green.
- **Track Q** — R2/R4/RTX/PLI-limit each have a dedicated test that fails on the
  pre-change code; soak runs are archived with their netem parameters.
- **Track C** — TURN/TLS and ICE-over-TCP are exercised against the `examples/`
  reference deployment in CI, not only locally.

## 6. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| macOS/Linux CI runners unavailable | E2 blocks; E1 baseline is Windows-only | Treat runner provisioning as the first task of M0; failing that, land compile-only Docker jobs for Linux and defer macOS with an explicit note |
| AEC activation regresses audio quality | E3 slips into v1.3.0 | Gate on ERLE measurement, not on "it compiles"; keep it behind a flag until measured |
| DXGI zero-copy publication needs driver-specific paths | E5 slips | Accept staging readback as a documented fallback and record which GPUs take which path |
| Stats surface churn after freeze | E1/S8 conflict | **Resolved by D-N6:** the freeze already happened; every later public field is an additive, reviewed manifest bump in the same PR. The risk is now *silent* drift, which the manifest diff makes visible at review time |
| E7 assumed an in-tree SCTP stack that does not exist | E7 (and therefore M0) slips | **Resolved by inspection:** the SCTP data plane was already retired from the public selector in v1.2.0, and the `"usrsctp"` factory has not been in the registry since v0.11.0. E7 turned out to be a *deletion* task, not a "write a stack" task — **it landed**; see the E7 block above |
| TURN/TLS handshake scope creep (auth mechanisms, long-term credentials) | C1 balloons | Restrict C1 to the RFC 5766 long-term credential mechanism; leave alternative auth to a later ADR |
