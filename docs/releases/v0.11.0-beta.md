# v0.11.0 Beta 前哨 — Release Notes

> **Cut 2026-10-09.** First minor to ship P2 content. API still
> **experimental / not for production** through v1.0.0.
>
> **Data-plane headline item (Chrome ↔ NimRTC DataChannel interop, DC-1)
> is NOT in v0.11.0.** The SCTP-over-DTLS physical wiring
> (`set_dtls_keys()` + DTLS↔SCTP inbound/outbound hookup) never landed on
> `main`; Chrome-headless e2e stays 0/4. v0.11.0 ships the **Chrome media
> interop** surface (audio + video Case D, all four platforms) and the
> L2 / L3 P2 scaffolding (TAP-1, PROFILE-1, DEMO-1, TPAL-4 cleanup),
> with the data plane explicitly deferred to the **v1.x WebTransport / QUIC**
> re-design. See `docs/plan/v0.11-plan.md` §2.2 / §10 for the full
> rationale and forward direction.

## TL;DR

- **Chrome media interop (audio + video Case D)** — green on Windows,
  Linux x86_64, macOS arm64, Linux aarch64. `python tools/run_e2e_acceptance.py --case d`.
- **PCM tap on WebRTC APM** — pre and post 3A taps are now first-class
  on the default `PluginAdapter`. Race-free setter semantics; AI-Agent /
  wake-word / streaming-ASR consumers can subscribe without an extra DSP
  integration.
- **5 Assembly Profiles** — `sfu` / `transport` / `agent` /
  `agent-gateway` / `sfu-agent` are first-class, backend-agnostic through
  PAL Slice 1/2/3. 32/32 strict round-trip tests pass.
- **DTLS seam** — `EngineConfig::dtls_name` field added (defaulted to
  `""` to preserve every v0.10.x caller source-compat). Engine resolves
  through `core::PluginRegistry::get_dtls_session(id)`. GMSSL /
  OpenSSL / BoringSSL / mbedTLS backends register their own id.
- **GitHub Discussions enabled** — community space alongside issues.
- **RFC 001 (PCM tap) promoted Draft → Final** — first formal design
  record under `docs/rfcs/`.
- **No binary artefacts shipped.** Source tree only.

## What's new

### Chrome media interop (audio + video Case D)

NimRTC ↔ Chrome audio Opus + video H.264 end-to-end via ICE + DTLS 1.3 +
SRTP + RTP. Verified across the four-platform CI matrix (windows-2022 +
linux-gcc + macos-clang + linux-aarch64). This is the v0.11.0 release
contract for media interop.

Reproduce locally:

```bash
git clone --recurse-submodules https://github.com/NimRTC/nimrtc
cd nimrtc
cmake --preset debug
cmake --build build
python tools/run_e2e_acceptance.py --case d
ls build/e2e/        # artifacts land here
```

### TAP-1 — PCM tap on WebRTC APM

`IAudio3A::set_pre_process_tap()` and `set_post_process_tap()` (RFC 001
§6.1–6.5) are now live on the default `PluginAdapter` implementation.
The WebRTC-APM-backed adapter fires pre and post 3A taps per
`process_capture()` call, so AI-Agent / wake-word / streaming-ASR
consumers can subscribe to:

- the raw mic PCM (pre), for wake-word models that prefer unprocessed
  audio, and
- the cleaned PCM (post), for streaming ASR that benefits from 3A cleanup.

Taps are `std::function`-based, install / uninstall via `nullptr`, and
guarded by a dedicated `tap_mu_` mutex so setters from any thread stay
race-free against the audio thread's `process_capture()` call (RFC §2.3
thread-safety contract). The post-tap is also delivered as `int16_t*`
with the same metadata.

Coverage: `tests/test_pcm_tap.cpp` 15/15 PASS.

### PROFILE-1 — Assembly Profile library officialised

Five profile variants are first-class and loadable at runtime:
`sfu` / `transport` / `agent` / `agent-gateway` / `sfu-agent`. PAL
Slice 1/2/3 (ADR-009) make all five backend-agnostic.

`tests/test_assembly.cpp` 32/32 PASS, including a strict
`JsonFileMatchesBuiltinConstant` regression test that loads every JSON
profile file and asserts field-by-field equality with the matching C++
constant. Two latent JSON↔C++ bugs uncovered by the new strict
round-trip test are fixed:

- `kProfileLive` now sets `scheduler.impl = "weighted_fair"` (was
  relying on the default while `live.json` declared `"weighted_fair"`).
- `profiles/sfu.json` now correctly sets `bwe_name = ""` (the comment
  said "Empty: no BWE" but the value was the string `"aimd"`).

### TPAL-4 — DTLS seam cleanup

`EngineConfig::dtls_name` field added (defaulted to `""` to preserve
every v0.10.x caller source-compat); engine resolves the DTLS factory
through `core::PluginRegistry::get_dtls_session(id)` at open() time
instead of direct `new DtlsSessionWolfSSL`.

- The `static_cast` escape hatch from v0.10.2 is gone.
- The `IDtlsSession` seam surface is tightened (every concrete method
  on `DtlsSessionWolfSSL` is now `override` against the seam).
- Future GMSSL / OpenSSL / BoringSSL / mbedTLS backends register their
  own id via `register_dtls_session(id, &factory)` and select via
  `cfg.dtls_name = "..."`.

Coverage: `test_engine_plugin_loading` 17/17 PASS (8 base + 5 Slice 8 +
2 Slice 7.5 + 5 new TPAL-4 subtests).

### DEMO-1 — AI Agent 接入 demo

`demo-agent-gateway` demonstrates the `agent-gateway` Profile end-to-end
with PCM tap → streaming ASR → LLM mock → response. See
`examples/demo-agent-gateway/README.md`.

### DISC-1 — GitHub Discussions enabled

Community now has a Discussions space alongside issues. Issue templates
updated to link to Discussions for "show & tell" and Q&A.

### RFC-1 — RFC 001 (PCM tap) promoted Draft → Final

First formal design record under `docs/rfcs/`. See
`docs/rfcs/001-pcm-tap.md`.

## What's not in v0.11.0 (data plane deferred to v1.x)

The following P2 headline items are explicitly cut from v0.11.0 and
moved to the v1.x WebTransport / QUIC re-design window — see
`docs/plan/v0.11-plan.md` §2.2 / §10:

- **Chrome ↔ NimRTC DataChannel bidirectional interop (DC-1)** — the
  SCTP-over-DTLS physical wiring was never landed on `main`; v0.11.0
  falls back to the in-process `test_datachannel_engine` 5/5 PASS as
  the §7 substitute, made permanent. v1.x will redesign the data plane
  on top of **WebTransport over QUIC** (likely msquic, MIT-licensed,
  Windows-first, cross-platform CI).
- **L1 strict-priority scheduling across the DC plane (DC-2)** — only
  meaningful once DC-1 lands. The RTP-only strict-priority path is
  already covered by `test_sched_priority.cpp` from v0.10.x.
- **usrsctp production backend (TPAL-5)** — the `UsrsctpSocket` class
  is `@deprecated` and still compiles and links for opt-in callers
  (the in-process `test_sctp_usrsctp` 4/4 PASS regression test
  continues to run), but `sctp::register_default_plugins()` no longer
  publishes id="usrsctp" with `core::PluginRegistry`. Expected removal:
  v1.2.0.

## Deferred to pre-1.0 decision window (unchanged from v0.11-preview)

- **In-process SFU relay (`nimrtc_sfu`)** — SFU forwarding has open
  architectural questions on BWE/JB interaction. Decision deferred to
  v1.0.0 commit. If community asks for it during v0.11.0 cycle, it
  lands in v0.11.x patch train.
- **DC forwarding policy (DC-3)** — dependent on SFU-1 AND v1.x DC-1
  WebTransport land; inherits both deferrals.
- **`sfu-relay` benchmark (BENCH-1)** — dependent on SFU-1.

## Migrating from v0.10.x

**Source-compat:** every v0.10.x caller continues to compile and link.

- The only public API change is the single `EngineConfig::dtls_name`
  field. Defaults to `""`, which selects the legacy wolfSSL backend
  (the same one v0.10.x was hard-wired to).
- `engine.hpp` adds one new field; everything else in the public API
  surface is unchanged.
- `dtls::test_only::get_wolfssl_factory()` and
  `sctp::test_only::get_stub_factory()` are preserved as back-compat
  accessors that now read back through the registry.

**Layout invariants preserved:**

- Invariant 1 (`src/core/` is the only INTERFACE library).
- Invariant 4 (no concrete module headers in `engine.hpp`).
- Invariant 6 (singletons in `nimrtc::core::`).

**Wire-compat:** the Chrome media interop contract is identical to the
v0.10.3 tech-preview. Existing peers (Chrome, Firefox, libwebrtc) do not
need to upgrade.

## Known issues / limitations

- **API experimental through v1.0.0.** Layout Invariant 4 (the
  `engine.hpp` includes discipline) is preserved, but smaller surface
  changes are expected across v0.11.x.
- **No public benchmark suite yet.** Throughput / latency numbers for
  the v0.11.0 build are in the README's "Benchmarks" section but are
  a hand-rolled subset, not a published harness. BENCH-1 is deferred
  with the SFU-1 family.
- **Wasm browser demo is on the v0.12.0 roadmap.** A scaffolding
  placeholder exists in `examples/wasm-demo/`; it does not yet build.
- **No iOS / Android native builds.** Both are roadmap, not P1.
