A from-scratch C++20 WebRTC engine.
~5.6 MB. Four platforms. No fork.

NimRTC is an embeddable media engine that keeps the wire-level WebRTC interop you need (Chrome, Firefox, libwebrtc peers) and replaces the 150–250 MB monolith with a layered, plugin-adapted engine you can grep, swap, and ship on aarch64. Same source tree ships a P2P client and an SFU gateway. DTLS, RTP, audio 3A, and codecs are all behind header-only plugin interfaces.

Quick start

Build the loopback example and run it locally. Total time on a clean clone: ~3 minutes on a 4-core x86_64. All third-party deps are git submodules, SHA-pinned in src/third_party/vendor.json.

  1. Clone (with submodules)
    git clone --recurse-submodules https://github.com/NimRTC/nimrtc.git
cd nimrtc
  2. Configure + build
    cmake --preset debug.msvc       # or: debug · debug.macos · debug.aarch64
cmake --build build --target loopback-p2p -j
  3. Run the smoke test
    ./build/examples/Debug/loopback-p2p      # or .exe on Windows
    Expected output: [A ice] connected and [B ice] connected within ~2–3 s, then exit code: A=1 B=1, returning 0.
  4. Run the test suite + Chrome interop e2e
    ctest --preset tests --output-on-failure
python tools/run_e2e_acceptance.py    # Chrome ↔ NimRTC Case D

What's working · what's not (be honest)

Shipped in v0.11.0

  • Chrome ↔ NimRTC P2P audio + video interop, Case D, on all four platforms (CI green).
  • 5-variant profile library (sfu / transport / agent / cloudgame / agent-sfu) with strict JSON↔C++ round-trip tests.
  • Pre/post-3A PCM tap (race-free set_pre_process_tap / set_post_process_tap, int16 ASR variant).
  • PAL Slice 1–8 — plugin-capability resolution, zero runtime overhead, public API unchanged.
  • Pluggable DTLS backend (EngineConfig::dtls_name resolves to OpenSSL / wolfSSL / mbedTLS at build time).
  • Vendored libs: wolfSSL · libsrtp · libopus · libjuice · WebRTC APM. SHA-pinned.

Deferred to v1.x (and why)

  • DataChannel over SCTP-over-DTLS. Chrome is moving DataChannel to WebTransport over QUIC; v1.x re-platforms on msquic. The usrsctp socket class is @deprecated and still compiles for opt-in callers.
  • iOS / Android native. Roadmap, not P1. No ETA yet.
  • Production-grade hardening. Lands in P3 / P4. v0.11.0 is a Beta 前哨 — API experimental through v1.0.0.

On the v0.12.0 roadmap

  • Wasm browser demo (this page is the placeholder; see below).
  • Adaptive jitter buffer + Goog-CC-style BWE (P3).
  • GMSSL DTLS backend for Xinchuang / GM/T (P4).

Architecture, in 30 seconds

Four compile-time layers (L0–L3) sit on top of a Plugin Adaptation Layer (PAL). A profile — also chosen at build time — decides which layers are even linked into the binary. The sfu profile literally omits L2 codecs from the link. 

┌─────────────────────────────────────────────────────────────┐
│  PROFILE  —  compile-time selection                          │
│  transport │ sfu │ agent-gateway │ cloudgame │ agent-sfu    │
└─────────────────────────────────────────────────────────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│ L3  Engine   │      │ L2  Codecs   │      │ L1  Wire /   │
│ NimRTCEngine │ ←──→ │ + 3A         │ ←──→ │ state        │
│              │      │ Opus / H.264 │      │ RTP / ICE /  │
│              │      │ VP8 / 3A    │      │ DTLS / SRTP  │
└──────────────┘      └──────────────┘      └──────────────┘
                              │
                              ▼
                    ┌──────────────────────┐
                    │  PAL  —  zero-       │
                    │  overhead resolver   │
                    └──────────────────────┘
                              │
                              ▼
        ITransport · IICETransport · IRTP · ISDP · IJB
        IAudio3A · ICodec · IVideoSource/Sink · IDtlsSession

Every capability swap (OpenSSL ↔ wolfSSL ↔ mbedTLS ↔ GMSSL; in-tree 3A ↔ HW 3A; libjuice ↔ custom ICE) flows through one of these header-only interfaces. The public NimRTCEngine API does not change.
