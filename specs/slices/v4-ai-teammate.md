# Slice: v4-ai-teammate

## 目的
把 M1 的假 AI 逻辑换成**本地小模型**：窄角色（只会「左移 / 右移 / 停」），
决策必须**带帧标签**（`frame_seq` + `capture_ts`），
并且「时光作证」的答案要 100% 带 `frame_seq + capture_ts`。

这是 M3 的第二条：观众问「为什么往左？」，AI 的回答必须能指回具体那一帧。
窄角色是刻意的 —— 小模型只做窄任务，才压得住延迟。

对应 `docs/plan/ai-game-demo-plan.md` §8 M3 第二、三条，以及 §4.2「时光作证」。

## 范围
- examples/demo-agent-realtime/**
- tests/acceptance/v4-ai-teammate/acceptance.test.cjs

## 需求
1. AI 决策由**本地小模型**产出（不是 mock 规则、不是云端 API）。
2. 角色是**窄的**：动作集合限定为「左移 / 右移 / 停」三类，不做开放聊天。
   模型给出集合外的动作时如实拒绝并计数，不静默改成别的动作。
3. 每条决策都带 `frame_seq` 与 `capture_ts_us`（§5.2 格式），
   且这两个值来自**模型实际看到的那一帧**，不是当前时刻。
4. 「时光作证」的回答 100% 带 `frame_seq + capture_ts`：
   回答里引用的帧必须是**已经滚出当前画面**的那一帧（不是当前帧）。
5. 决策的输入是画面语义（该帧上有什么），不是笼统的「用户说了什么」。
6. 模型不可用时明确报错并计数，不静默退回 mock 规则（除非调用方显式要求退回）。

## 验收标准
1. 决策路径上存在本地模型推理的调用点；验证方式：静态检查推理调用存在
2. 动作集合被限定为三类，且集合外的动作被拒绝并计数；验证方式：静态检查动作白名单与拒绝分支
3. 每条决策的 `frame_seq` 与 `capture_ts_us` 非空且来自被观测帧；验证方式：单元测试构造一次决策，断言两个字段取自传入的帧观测而非当前时刻
4. 回答里引用的帧是历史帧（帧号小于当前帧号）；验证方式：单元测试在「引用旧帧」的场景下断言引用帧号小于当前帧号
5. 模型不可用时报错并计数；验证方式：静态检查模型缺失分支的错误输出与计数点

## 风险
1. 小模型推理耗时几十到几百毫秒 → 决策滞后于画面；应对：把推理耗时打进统计；这是「窄角色 + 本地」而非「大模型」的原因
2. 窄角色在演示里显得「不聪明」，观众可能觉得糊弄；应对：处刑台的看点是**延迟差**（`age_us`），不是决策质量
3. 模型输出格式不稳定（JSON 偶尔不合法）→ 解析失败；应对：解析失败时重试一次，仍失败就计数并如实报告，不编造动作
4. 引用帧已滚出画面是**前提**（§4.2），实现时容易顺手引用当前帧 → 演示效果失真；应对：需求 4 明确成硬验收项
