# Slice: v5-writeset-acceptance

## 目的
把 M1–M4 四片的**写集边界断言**从「读未提交的工作区差异」改成「读提交历史」。

现状（实测 D-68，2026-11-18）：四个验收套件在**已提交的干净树上必红**。

```
v1-video-processing  pass 1  fail 3
v2-ai-decision       pass 5  fail 1
v4-ai-teammate       pass 7  fail 1
v4-voice-agent       pass 7  fail 1
```

四个失败是同一个病灶：断言读的是 `git diff --name-only`（工作区 vs 索引）。
切片一旦被提交（`feat(<id>): slice approved`），工作区差异为空 →
「写集内必须存在已追踪文件的改动」这条断言必然不成立。

这不是「测试写得不对」这么轻：**验收测试自己把「已交付」的状态判成「没交付」**。
合并前在 worktree 里跑是绿的（工作区有差异），合并后 / CI 里跑是红的 ——
门禁②验证的东西与签字之后的状态不一致。

判据要改成**提交历史**：本片的产物在 `Refs-Slice: <id>` 提交里，
看提交历史就能回答「本片改了哪些文件」，与工作区状态无关。

## 设计
写集边界要回答的问题是「**本片 agent 改了什么**」。
这个问题的答案有三个来源，各自在不同状态下才拿得到：

| 来源 | 什么时候有 | 覆盖什么 |
|---|---|---|
| 工作区未提交差异（`git diff --name-only`） | agent 正在干活时 | 还没提交的那部分改动 |
| 本片自己的提交（`Refs-Slice: <id>` trailer） | 合并前提交之后 | 本片已提交的改动 |
| 未跟踪文件（`git ls-files --others`） | 任何时候 | agent 新建还没 add 的文件 |

现状只用第一个来源，于是**提交之后第一个来源变空** —— 断言判「本片没产物」，
而本片明明有产物。这就是要修的病灶。

修法：三个来源**并起来**判。判据从「工作区差异非空」改成
「工作区差异 ∪ 本片提交差异 ∪ 未跟踪文件，非空」。

本片自己的提交怎么找：`git log --format=%H%x00%B%x00%x00 <base>..<head>`
解析出带 `Refs-Slice: <id>` trailer 的 commit，逐个算
`git diff --name-only <commit>^..<commit>`。
这与 zelto 自己的写集审计同一口径 ——
**验收测试与运行时审计用同一套判据**，两边不会各说各话。
（zelto 侧那份实现在它自己的仓库里，本片只读不改它。）

越界检测不削弱：三个来源并起来之后，仍要逐个判「是否落在写集内」，
落在外面就判 failed。改的只是「本片改了哪些文件」这个问题怎么答。

`tests/acceptance/**`（除非对应切片规格一起改并重新 freeze）」。
本片改的四个套件对应的旧切片（v1-video-processing / v2-ai-decision /
v4-ai-teammate / v4-voice-agent）都已完成并交付，它们的规格**不改**——
因为那四片的**验收标准本身没变**（「本片改动仅限 X 模块」这类约束仍然成立），
变的只是**验证手段**（从「读工作区差异」换成「读提交历史」）。
本片的规格已经人确认并冻结，它就是这次改动授权的出处。

## 需求
1. 四片的写集边界断言改读**提交历史**（本片自己的提交 + 工作区未提交差异 +
   未跟踪文件三者并集），不再单看 `git diff --name-only`。
2. 判据要能在**两种状态**下都成立：
   - 切片自己的 worktree 里（工作区有未提交改动）→ 绿；
   - 已提交的干净树上（主干、CI）→ 绿。
   不能靠「断言消失」或「断言改成永远为真」来达成。
3. 越界检测能力**不得削弱**：仍须拦下「本片改动了写集之外的文件」。
   验证方式：构造一个越界改动（一个写在写集之外的文件），
   断言检查逻辑判 failed。
4. 判据必须**确定性**：同一棵树、同一提交历史，重复跑结果一致
   （不依赖时间、不依赖网络、不依赖随机、不依赖环境变量）。
5. 四个套件用**同一套判据**（共用一份实现，不各写一份）——
   两份实现必然漂移，而漂移的方向恰好是「漏掉一条路径」。
6. 不得修改各片的**业务实现**（`examples/demo-agent-realtime/**`、
   `src/modules/**`）——本片只动验收测试。
7. 判据不得依赖**外部网络**或**模型**（验收测试必须是确定性计算）。

## 验收标准
1. 四个套件在**干净已提交树**上全部通过；验证方式：在已提交的主干树上
   逐个跑四个套件的验收命令，四条命令退出码均为 0
2. 四个套件在**有未提交改动**的工作区上同样通过；验证方式：制造一处未提交改动后
   重跑，退出码仍为 0（断言不因工作区状态而翻转）
3. 写集边界断言仍能拦下越界改动；验证方式：套件里的判据实现被一个越界场景调用，
   断言它返回「越界」
4. 四个套件共用同一套判据实现；验证方式：静态检查四份套件源码，
   写集边界那条用例都调用同一份共用实现
5. 判据是确定性的；验证方式：同一套件连跑两次，退出码与逐条用例结果一致
6. 业务实现未被改动；验证方式：本片提交的文件清单只落在验收测试范围内
7. 判据不触网、不调模型；验证方式：静态检查共用实现里没有 http/网络调用

## 风险
1. 提交历史里混进别的提交（基点算错）→ 越界误报 / 漏报；
   对策：以**基点 commit** 为起点算差异，基点取本片记录里的 `baseCommit`
2. 合并 commit（`Merge slice <id>`）把多片产物合在一起 → 差异里混进别的片；
   对策：按 `Refs-Slice: <id>` trailer 过滤出本片自己的提交，逐个算差异
3. 切片还没提交时（agent 正在干活）跑验收 → 提交历史为空 → 断言不成立；
   对策：断言同时看**工作区差异**与**提交历史**，两者并集为空才判「本片没产物」
4. 改坏四个套件里的其它断言 → 对策：门禁②跑全套件，
   逐条用例结果与改动前比对（不只看退出码）
